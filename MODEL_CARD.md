# ForteVision: модель, результаты и оборудование

Репозиторий содержит код анализа видео, обучения и оценки адаптеров.
Веб-интерфейс существует отдельно; эксперимент InternVideo не подключён к нему.
Публичный сервис для жюри не заявляется как развёрнутый.

## Базовая модель

`OpenGVLab/InternVideo2_5_Chat_8B`, ревизия
`87680fe232af8681b55322f68541679b91f99df1`.
[Официальная страница](https://huggingface.co/OpenGVLab/InternVideo2_5_Chat_8B).
Веса загружаются скриптами из `deploy/internvideo`; проверяется закреплённый
манифест. После установки обработка выполняется на собственном GPU-сервере,
без передачи записей, кадров или описаний во внешние AI API.

Обучаются собственные LoRA-матрицы attention-проекций последних 12 слоёв,
rank=8. Визуальный кодировщик и остальные исходные веса заморожены. Формат
адаптера собственный, он не загружается напрямую через PEFT `from_pretrained`.

## Измеренный результат events-v2

40 уникальных видео, 21 положительное и 19 отрицательных; пять разбиений
24 обучения / 8 калибровки / 8 теста. Дубликаты объединены по SHA-256.

| Метрика | Исходная модель при той же подготовке | После обучения |
|---|---:|---:|
| Accuracy | 52,5% | 55% |
| Верная норма / ложная тревога | 6 / 13 | 10 / 9 |
| Пропуск / найденное нарушение | 6 / 15 | 9 / 12 |
| Precision | 53,57% | 57,14% |
| Recall | 71,43% | 57,14% |

У 9 из 21 положительных видео хотя бы один интервал-кандидат содержит размеченный
таймкод. Это не точность границ или категорий действий. Источник — вывод
завершённого серверного запуска, предоставленный пользователем; для воспроизведения
и экспорта используются исходные `result.json` на сервере.

Качество недостаточно для самостоятельных решений о нарушениях. Категории и роли
людей не размечены; идентификация лиц не выполняется. Набор многократно использован
в разработке; новый ракурс и независимые записи не проверены.

Новая схема обучения описана в [EVENTS_V3.md](deploy/internvideo/EVENTS_V3.md).
До её завершённой проверки нельзя приписывать ей 55%, 75% или 85% точности.

## Вычислительные ресурсы

| Компонент | Использованная конфигурация Brev |
|---|---|
| GPU | 1 × NVIDIA L40S, 48 ГБ VRAM |
| Оперативная память | 32 ГиБ |
| CPU | 4 vCPU, x86_64 |
| Диск | 256 ГиБ |
| Среда | Linux, Python, PyTorch 2.6.0 с CUDA 12.4, Transformers 4.37.2 |

Это проверенная конфигурация, а не измеренный минимальный порог для каждого
компонента. Скрипт обучения требует не менее 40 ГиБ VRAM. В показанных логах v2
пиковое выделение PyTorch составляло около 27 ГиБ; это не вся память процесса
и не гарантия работы на GPU с 27 ГиБ. Пиковая память полной v3 ещё не измерена.

Базовые файлы весов занимают около 16,8 ГБ. Дополнительно нужны зависимости,
видеоданные, замороженные входы, временный кэш кадров и результаты обучения.
Настройка для 8-ГБ ноутбука для этой InternVideo-конфигурации не подготовлена.

## Получение и демонстрация весов

Обученные серверные веса не появляются в GitHub автоматически после `git push`.
Команда `export_adapters.py` в [инструкции](deploy/internvideo/EVENTS_V3.md)
создаёт архив с пятью адаптерами, порогами, контрольными суммами и отчётами.
Прикрепите полученный архив к Release вместе с кодом соответствующего коммита.
Базовые веса скачиваются отдельно из закреплённой ревизии.

Не выбирайте «лучшую модель» по точности на тестовом разбиении. Для демонстрации
можно заранее зафиксировать fold 0 и явно указать, что это адаптер одного
разбиения. Оценивать его на его обучающих видео как на независимом тесте нельзя.
Архив не содержит единого окончательного адаптера, обученного на всех данных.

Результаты анализа отдельного видео — интервалы для проверки человеком,
а не доказанные дисциплинарные или юридические нарушения.
