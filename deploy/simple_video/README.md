# Одна Qwen: обучение и проверка на L40S

Используется уже установленная **Qwen3-VL-8B-Instruct**. Она один раз вычисляет признаки каждого видео; небольшой бинарный классификатор обучается на этих признаках и метках «нарушение / норма». Базовые веса Qwen заморожены: это обучение классификатора поверх модели, а не LoRA или полное дообучение Qwen. Другие нейросети не загружаются. Всё выполняется локально, без внешних API и новых скачиваний.

## Обучение

Если старый ансамбль ещё работает, остановите его через Ctrl+C в его терминале, чтобы освободить GPU. На сервере выполните:

```bash
cd ~/Datathon &&
git pull --ff-only &&
cd deploy/simple_video &&
../ensemble/.venv/bin/python train_head.py --dataset ../internvideo/open-dataset --model ../ensemble/models/qwen --output results/qwen-single-v1
```

Используются существующее окружение `deploy/ensemble/.venv` и каталог модели `deploy/ensemble/models/qwen`. Название каталога не означает запуск ансамбля. Новая установка не нужна: нужный scikit-learn уже входит в его зависимости.

Сначала проверяются видео и локальные веса. Затем появляются сообщения `qwen_features`, по одному на видео. Qwen делает один проход на фрагмент без генерации текста и без обратного распространения. Для роликов до 150 секунд фрагмент один. Признаки сохраняются в `results/qwen-single-v1/features`. Повторный запуск той же команды использует сохранённые признаки; изменения модели, кода, разметки или настроек требуют нового каталога результатов.

После извлечения признаков выполняются пять небольших обучений классификатора на CPU. Это пять разбиений для внутренней оценки, а не пять повторных прогонов видео через GPU. В каждом разбиении отдельные видео используются для обучения, подбора порога и теста. Для текущих 40 уникальных видео это 24 / 8 / 8; каждое видео попадает в тест один раз. Нормализация признаков обучается только на обучающей части. Порог подбирается только на калибровочной части с учётом ложных тревог и пропусков; он не гарантирует отсутствие ошибок.

Результаты:

- `predictor.json` — обученный классификатор и порог для заранее выбранного разбиения 0. Не выбирается лучший результат по тесту; этот файл не обучен на всех 40 видео.
- `summary.json` — общие метрики на отложенных частях пяти разбиений, включая ложные тревоги и пропуски. Это оценка процедуры обучения, а не отдельное измерение экспортированного классификатора на всех 40 видео.
- `evaluation.json` — результаты отдельных разбиений и числовые предсказания.
- `protocol.json` — хеши весов, исходников, разметки и настройки для совместимости кэша и классификатора.

При обычной остановке Ctrl+C блокировка снимается. Если процесс был аварийно уничтожен и остался `.training.lock`, сначала убедитесь, что обучение больше не работает, затем удалите только этот файл в каталоге результатов.

## Проверка нового видео

Из `deploy/simple_video` после обучения:

```bash
../ensemble/.venv/bin/python run.py --video /path/to/new.mov --head results/qwen-single-v1/predictor.json --output results/check-v1
```

Укажите существующий путь к видео и новый каталог `--output`. Основной режим получает признаки одним проходом Qwen и выдаёт бинарный вердикт через обученный классификатор. Проверяются хеши модели и настроек, поэтому для переноса нужны исходная Qwen, `predictor.json` и совместимая версия исходников. Небольшой JSON не содержит базовые веса Qwen.

Опция `--locate` после положительного вердикта дополнительно просит **ту же Qwen** предложить категорию и таймкод, сохраняет кандидатный кадр. Это увеличивает время; предложенный кадр требует проверки. Классификатор обучается только бинарной метке, не категориям, ролям или точным таймкодам. Краткий ответ модели ограничен JSON-схемой; корректный формат не доказывает правильность события. Отсутствие обязательного действия нельзя подтвердить только промежутками между выбранными кадрами.

Без `--head` доступен прямой экспериментальный анализ Qwen с кратким структурированным ответом. Это отдельный режим без обучения классификатора.

## Покрытие и время

Видео до 150 секунд передаётся в одном контексте с хронологией и примерно 1,5 кадрами в секунду. Число кадров растёт с длительностью, общего ограничения 120 кадров нет. Более длинные записи делятся на 150-секундные фрагменты с перекрытием 10 секунд; их признаки усредняются с весом по длительности. Этот режим не проверен на длинных записях и может ослаблять короткие события.

Декодируются все исходные кадры, но модель видит только выборку. Короткое действие между выбранными кадрами может быть пропущено. Кадры уменьшаются с сохранением пропорций, длинная сторона не больше 448 пикселей; мелкие предметы могут быть неразличимы. Таймкоды рассчитываются по номеру кадра и FPS; точность PTS для переменного FPS не подтверждена. Идентификация лиц не выполняется.

Время каждого видео включает декодирование и обработку. Начальная загрузка модели и проверка хешей учитываются отдельно в общем времени. Ориентир — до минуты на ролик на L40S; пока это цель, а не измеренный результат или жёсткий таймаут. По просьбе пользователя финальная версия подготовлена без новых запусков модели и тестов на ноутбуке; проверена структура кода. Обучение и качество требуют запуска на сервере.

Эти 40 видео уже использовались при разработке. Даже отложенные части здесь остаются внутренней оценкой; новые ракурсы и неизвестные нарушения не проверены. Обучение не гарантирует 85% или отсутствие ошибок. Выходной JSON пока не подключён к сайту и не является готовой схемой API жюри.
