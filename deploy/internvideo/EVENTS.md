# Фрагменты, движение и визуальный контекст

Экспериментальная версия использует всю временную шкалу, без одного общего
лимита кадров на ролик. Серверные метрики нового обучения ещё не получены.
Автоматические вердикты приложения не включаются.

Локальная проверка исходных данных: все 40 уникальных роликов прошли полный
поиск движения — 38 908 декодированных кадров, 115 окон, все размеченные времена
попали в группы окон. Это проверка декодирования и планирования, не точности ИИ.
Обучающий цикл проверен на синтетических признаках с уменьшенной InternVideo,
реальным токенизатором и кодом модели. Полное новое обучение на L40S ещё предстоит.

## Обработка

1. OpenCV декодирует каждый кадр, уменьшает до 160×96 и измеряет изменение
   яркости в небольших областях. Это поиск движения, не распознавание действий.
   Ошибка декодирования не скрывается.
2. Фрагменты по 16 секунд перекрываются на 4 секунды. Последний заканчивается
   у конца файла. На длинной записи увеличивается число фрагментов, а не
   уменьшается частота выборки.
3. В каждом фрагменте сохраняется равномерная выборка около 4 кадров/сек.
   Добавляются кадры пиков локального движения и их соседи; всего до 96 кадров
   подробного просмотра. Шум и изменение освещения тоже могут давать пики.
4. Добавляются до 32 кадров из прошлого этого же видео: равномерные ориентиры
   от начала и заметные изменения. Будущие кадры в историю не попадают.
   Итого до 128 кадров 448×448 на фрагмент. Повторы для четырёхкадровых групп
   не создают новой информации.
5. Модель получает абсолютное время кадров и границы текущего интервала.
   Предыдущие ответы модели не используются как установленные факты.

Семантически видеомодель смотрит только выбранные кадры. Каждый исходный кадр
проходит дешёвый поиск движения. Неподвижный мелкий предмет, слабое движение
или плохо различимая деталь всё ещё могут быть пропущены. Визуальная история
ограничена; это не точная долговременная память и не трекер людей. Роли кассира
и клиента пока не устанавливаются отдельной проверенной системой. Время
рассчитывается по номеру кадра и FPS; PTS для VFR не проверены.

## Обучение по таймкодам

`train_events.py`: пять разбиений по целым уникальным видео — 24 обучения,
8 калибровки, 8 теста. Один ролик не попадает одновременно в обучение и тест.

Для положительного обучающего видео выбирается группа окон с размеченным
временем. Метка относится к группе: достаточно события хотя бы в одном окне.
Остальные окна не объявляются нормальными. Разные таймкоды точного дубликата
сохраняются как альтернативы внутри группы. Это слабая временная разметка,
а не точные границы или категория действия.

Для нормального обучающего видео используются наиболее подозрительное окно
по исходной модели и дополнительное случайное окно (или все, если их не
больше двух). Каждое видео даёт один вклад в ошибку независимо от длины.
Оценка группы — максимум бинарных оценок окон; градиент получает наиболее
подозрительное окно. Обучаются только LoRA rank=8 последних 12 слоёв.

На калибровке и тесте обрабатываются все окна. Эпоха и порог выбираются только
по калибровке. Отчёт показывает FP/FN и долю положительных видео, где кандидат
содержит размеченное время; это не точность границ события. Исходная модель
проверяется на такой же выборке кадров.

Максимум по многим окнам может увеличить ложные тревоги с длиной видео.
Короткий открытый набор не доказывает качество на часовых записях; отчёт
явно отмечает это ограничение. Повторяющийся ответ не является доказательством.

## Запуск

Исправление MOV-декодера: выбранные кадры теперь читаются последовательно из заново
открытого файла, без случайных переходов по `CAP_PROP_POS_FRAMES`. На X-2 прежний
переход к кадру 508 завершался ошибкой, хотя последовательное чтение работает.
Номер кадра определяется порядком успешного чтения. Пропущенный или повреждённый
кадр не заменяется соседним; ошибка остаётся явной.

Выбранные изображения после того же уменьшения до 448×448 сохраняются без потерь
во временные PNG внутри каталога результатов и используются повторно для истории
и перекрытия. В памяти остаётся один фрагмент; временный диск растёт с числом
уникальных выбранных кадров одного видео. Кэш удаляется при выходе из обработки
ролика, в том числе при обычном исключении или Ctrl+C. При принудительном завершении
процесса временный каталог может остаться.

После обновления декодера используйте новый `--output results/events-v2`:
старый `events-v1` содержит протокол с другими хешами кода и не должен смешиваться
с новым запуском. Скачанные исходные веса остаются прежними.

Проверка исправления на локальных исходных MOV: 40/40 видео, 115/115 фрагментов,
12 556 позиций кадров с историей и повторами; размеры тензоров, конечность значений
и временные отметки проверены. Последовательное чтение дошло до конца каждого
из 40 видео (38 908 исходных кадров). Все 51 автоматическая проверка прошли.
Путь анализа с адаптером также прошёл на синтетическом видео с уменьшенной
InternVideo и BF16 CUDA. Это проверка декодера и интеграции, а не результат
обучения полной 8B-модели на сервере и не измерение качества распознавания.

Не запускайте одновременно со старым обучением на той же GPU. Дождитесь его
завершения либо остановите Ctrl+C; завершённые разбиения останутся. Новая
версия использует отдельный каталог, исходные веса и новые оптимизаторы.

```bash
cd ~/Datathon && git pull --ff-only && cd deploy/internvideo
.venv/bin/python train_events.py --dataset open-dataset --output results/events-v2
```

Повторная установка и скачивание весов не нужны. Этапы:
`event_inputs` → `matched_window_baseline` → `event_training` →
`event_epoch_complete` → `event_fold_complete` → `finished`.

```bash
cat results/events-v2/summary.json
```

`--max-folds 1` запускает одно разбиение; повтор без флага продолжит остальные.
`--prepare-only` проверяет манифест и фиксирует протокол без GPU, но ещё не
проверяет декодирование. При перезапуске готовые признаки и разбиения
используются повторно, незавершённое разбиение начинается заново. Поиск
движения повторяется. При изменении кода, данных или параметров нужен новый
`--output`.

## Отдельное видео

Проверка покрытия без загрузки модели:

```bash
.venv/bin/python analyze_windows.py path/to/video.mov --plan-only
```

Экспериментальный анализ исходной моделью:

```bash
.venv/bin/python analyze_windows.py path/to/video.mov --output results/window-check-1
```

После обучения, с адаптером конкретного разбиения:

```bash
.venv/bin/python analyze_windows.py path/to/video.mov --adapter-run results/events-v2 --fold 0 --output results/window-adapter-check-1
```

Адаптеры прежнего `lora-v1` не подходят: контекст другой. Проверяются параметры,
версия кода, ревизия модели и хеш весов. Анализ обучающего ролика адаптером
не является независимой проверкой качества.

`plan.json` содержит выбранные индексы, `windows.json` — результаты окон,
`summary.json` — завершённость и интервалы кандидатов. Несколько окон могут
относиться к одному действию; это не число нарушений. Итог остаётся
`inconclusive`, `violations` пуст, нужна проверка человеком. Все отрицательные
окна тоже не доказывают отсутствия нарушения. Ошибки сохраняются в логах;
неполное покрытие явно отмечается.
