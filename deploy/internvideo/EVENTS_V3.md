# Обучение v3 и проверка ошибок

Завершённый запуск `events-v2` на Brev дал TN=10, FP=9, FN=9, TP=12 на 40
отложенных видео: accuracy 55%, precision/recall 57,14%, FPR 47,37%. Сопоставимая
замороженная модель: TN=6, FP=13, FN=6, TP=15, accuracy 52,5%. Источник этих
результатов — предоставленный пользователем вывод `finished`; полный серверный
отчёт не копировался на локальный компьютер. Это результат v2, не v3.

## Изменения

- Каждый фрагмент нормального обучающего видео получает отрицательный BCE-loss.
  Потери делятся на число фрагментов, поэтому длинное видео не получает больший
  общий вес. Раньше выбирались только два фрагмента, а hard max давал градиент одному.
- Положительная группа по размеченному времени обучается через нормированный
  log-mean-exp вместо hard max. Градиент получают все фрагменты группы; прочие
  фрагменты положительного видео не объявляются нормальными.
- Положительная группа считается в два прохода с воспроизведением состояния RNG,
  чтобы dropout совпадал. Это даёт тот же градиент, что совместное вычисление,
  но в памяти хранится граф одного окна. Несовпадение оценок останавливает запуск.
- Два выходных логита вычисляются в FP32. Прежний BF16-расчёт округлял значения
  до преобразования в FP32 и терял малые различия классов.
- Максимум 6 эпох, минимум 3, остановка после двух эпох без улучшения калибровки;
  learning rate 5e-5. Выбирается лучшая эпоха, включая нулевую исходную модель.
- После эпохи сохраняются отдельные метрики обучения и калибровки. Для тестовых
  видео сохраняются все оценки окон, включая отрицательные, и исходные оценки.

Критерий выбора порога и эпохи остаётся прежним, по калибровке. Тестовые метки не
используются для этих решений. Итоговая оценка видео всё ещё равна максимуму
оценок окон; смещение из-за числа окон полностью не устранено.

## Запуск на существующей L40S

```bash
cd ~/Datathon && git pull --ff-only && cd deploy/internvideo
.venv/bin/python train_events_v3.py --dataset open-dataset --cache-run results/events-v2 --output results/events-v3 --check-only
.venv/bin/python train_events_v3.py --dataset open-dataset --cache-run results/events-v2 --output results/events-v3
```

`--check-only` проверяет хеши, идентичность данных, план кадров и формат сохранённых
признаков без загрузки 8B-модели. Если проверка не прошла, обучение не запускайте;
не редактируйте контрольные суммы вручную. Обычный запуск тоже делает эту проверку.

Повторное извлечение кадров и скачивание базовых весов не нужны. `events-v2`
используется только для чтения замороженных входов; его адаптеры не используются
как начальные веса. Каждое новое разбиение начинает с той же базовой модели.
Старые кодировщик, промпт, плотность кадров и код извлечения остаются прежними.

Пять разбиений по 24/8/8 видео. `--max-folds 1` ограничивает запуск первым
разбиением; повтор без этого флага продолжает остальные. Прерванное незавершённое
разбиение начинается заново. Изменение кода/гиперпараметров требует нового `--output`.

```bash
cat results/events-v3/summary.json
```

Дополнительные результаты: `error-audit.json` (ошибки, таймкоды, запас до порога,
число окон), `fold-*/progress.json` (кривые обучения), `fold-*/result.json`
(все тестовые оценки), `fold-*/adapter.safetensors` (выбранные веса).

Для разбора уже завершённого v2 без новой GPU-обработки:

```bash
.venv/bin/python event_diagnostics.py --dataset open-dataset --run results/events-v2 --output results/events-v2-audit
```

## Проверка отдельного видео

```bash
.venv/bin/python analyze_windows.py path/to/video.mov --adapter-run results/events-v3 --fold 0 --output results/v3-video-check-1
```

Используется FP32-голова v3, проверяются версия базовой модели, хеши весов,
подготовки входа и параметры кадров. Вывод содержит интервалы-кандидаты; это
экспериментальный анализ с ручной проверкой. Категории нарушений и роли людей не
обучены отдельно. Не выбирайте номер разбиения по его тестовой точности.

## Экспорт обученных адаптеров

```bash
.venv/bin/python export_adapters.py --run results/events-v3 --dataset open-dataset --output ../../ForteVision-events-v3-adapters.zip
```

Экспорт требует пять завершённых разбиений. В архив входят пять адаптеров,
пороги, протокол и измеренные результаты. Это пять моделей перекрёстной проверки,
а не одна модель, обученная на всех 40 видео. Архив не содержит исходных видео,
кадров, кэшей, ключей или базовых весов. Его можно скачать через Jupyter и
прикрепить к GitHub Release. До фактической загрузки архива веса не опубликованы.
Аналогичная команда с `events-v2` экспортирует уже завершённый старый эксперимент.

## Что проверено

Проверены градиенты всех отрицательных окон, совпадение двухпроходного MIL с
прямым расчётом при dropout, сохранение замороженных весов, непересечение
обучения/калибровки/теста, выбор и восстановление эпохи, контроль кэша и экспорт.
Уменьшенная модель с реальным кодом InternLM2 прошла обучение с checkpointing
на CPU и BF16 CUDA. Полная 8B-v3 ещё не оценена на реальных видео.

Дополнительный локальный эксперимент на уже сохранённых признаках Qwen2,
Qwen4 и R3D дал 57,5% для выбора семейства/линейного классификатора по калибровке.
Контроль только по длительности дал 65% и не использовался как визуальный детектор.
Эти результаты не подтверждают путь к 85%; они сохранены как отрицательный результат.

Этот открытый набор многократно использовался при разработке. Даже улучшение
внутренней оценки не доказывает перенос на новые записи и ракурс. 85% не заявлены
как достигнутый результат. Автоматические обвинения и сайт не включаются этим скриптом.
