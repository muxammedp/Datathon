# InternVideo: первый запуск на сервере

Этот пакет устанавливает InternVideo2.5-8B, запускает экспериментальный анализ и содержит отдельный скрипт бинарного дообучения LoRA. Трекинг ролей, память между фрагментами и подключение InternVideo к сайту пока не реализованы. Не считать установку модели обучением или подтверждением качества.

## Запуск в Jupyter

### Обновления через Git для уже установленного сервера

Если модель и данные уже находятся в `~/forte-internvideo`, один раз выполните:

```bash
git clone https://github.com/muxammedp/Datathon.git ~/Datathon
cd ~/Datathon
python3 deploy/internvideo/connect_existing.py ~/forte-internvideo
cd deploy/internvideo
.venv/bin/python evaluate_dataset.py --dataset open-dataset --output results/baseline --retry-failed
```

Если репозиторий приватный, GitHub потребует авторизацию пользователя. Не вставляйте
токены в URL репозитория. Если `~/Datathon` уже существует, сначала проверьте его
содержимое: повторное клонирование поверх существующей папки не требуется.

Скрипт создаёт только ссылки на `.venv`, `models`, `open-dataset`, `results` в новой
копии кода; оригиналы остаются в `~/forte-internvideo`. Он отказывается заменять
существующие файлы. Старую папку нужно сохранить. Установка и обучение не запускаются.
Ссылки и данные исключены из Git. Веса повторно скачивать не нужно.

Для последующих обновлений после завершения текущего запуска:

```bash
cd ~/Datathon
git pull --ff-only
cd deploy/internvideo
```

Теперь запускайте скрипты из `~/Datathon/deploy/internvideo`. Если изменились
параметры или код анализа, используйте новый каталог `--output`, чтобы не смешивать
результаты разных версий. Обновление Git само по себе не начинает обучение и не
меняет уже работающий Python-процесс.

### Установка с нуля из архива

Загрузите ForteVision-InternVideo-server.zip стрелкой Upload в файловой панели Jupyter. В Terminal выполните из папки с архивом:

```bash
python3 -m zipfile -e ForteVision-InternVideo-server.zip .
cd forte-internvideo
bash setup.sh
```

Установка создаёт отдельное окружение .venv, проверяет CUDA и скачивает около 16.8 ГБ весов. Требуются Linux, Python 3.10–3.12, GPU с минимум 40 ГБ памяти и 45 ГБ свободного диска. Компиляция FlashAttention не требуется. Время установки зависит от скорости сети. Аренда сервера продолжает оплачиваться во время установки и простоя; скрипт не управляет оплатой или остановкой инстанса.

После установки загрузите разрешённое видео в эту папку и выполните:

```bash
.venv/bin/python analyze.py "example.mov" --output results/first-video.json
```

Это анализ исходной моделью без дообучения. Ответ экспериментальный, он не передаётся в рабочий API и не является подтверждением нарушения. Параметры по умолчанию: около 4 кадров/сек, максимум 256 выбранных кадров, 448×448, вся выборка в одном контексте. Это НЕ каждый исходный кадр. Кадры кодируются партиями по 16 с сохранением четырёхкадровых групп компрессии. По пользовательскому скриншоту проверка 40 видео на L40S завершена после повторного запуска: точность 55%, 14 ложных тревог, 4 пропуска. Подробности — в BASELINE.md.

## Обучение LoRA на Brev

Из терминала после завершения проверки исходной модели:

```bash
cd ~/Datathon && git pull --ff-only && cd deploy/internvideo
.venv/bin/python train_lora.py --dataset open-dataset --output results/lora-v1
```

Дополнительные пакеты устанавливать не требуется. `train_lora.py` действительно
вычисляет градиенты и меняет веса адаптеров; `evaluate_dataset.py` этого не делает.
Порядок сообщений: `prepare_inputs` (подготовка замороженных признаков),
`matched_frozen_baseline` (сопоставимая исходная версия), `training` (обновление
весов), `epoch_complete`, `fold_complete`, `finished`.

По умолчанию выполняются пять разбиений по 24 обучающих, 8 калибровочных и 8
тестовых видео, по три эпохи. Каждый уникальный ролик ровно один раз находится
в тестовой группе; точные дубликаты исключены. Похожие постановки и одни и те же
участники могут оставаться в разных группах: меток независимых сцен в таблице нет.
Это внутренняя проверка на маленьком наборе, а не доказательство обобщения на другие камеры.

Выборка: до 128 кадров по всей длительности, 448×448, около 4 кадров/сек до
достижения лимита. Это не каждый исходный кадр. Ограничение 128 позволяет уменьшить
расход памяти при обратном распространении; фактический расход на L40S ещё нужно
проверить. В сравнении до/после используется одинаковая выборка и бинарные логиты,
поэтому отчёт отдельно называет прежнюю 256-кадровую генеративную проверку.

Заморожены визуальный кодировщик, проекция и базовые веса языковой модели.
Обучаются LoRA rank=8 в `wqkv` и `wo` последних 12 слоёв; накопление градиентов —
4 ролика, AdamW, learning rate 1e-4. Используется gradient checkpointing, а логиты
вычисляются только для двух ответов в последней позиции. Файлы и правильные
ответы не включаются в текст запроса. Метки и время события не входят в кэш признаков.

Порог и эпоха выбираются только на калибровочной группе. Критерий учитывает
ложные тревоги и пропуски, требует recall не ниже 0.5 на калибровке; при равенстве
используется log loss. Состояние до обучения также участвует в выборе: `epoch: 0`
означает, что сохранена исходная модель, а не успешное дообучение.

Краткий результат: `results/lora-v1/summary.json`; полный: `metrics.json`, в них `held_out_metrics` и
`matched_frozen_metrics`; веса каждой проверенной версии сохраняются в
`fold-*/adapter.safetensors`. Формат адаптера собственный: `forte_torch_lora_v1`,
не PEFT. Для загрузки используются `attach_adapters` и `restore_adapter` из
`lora_binary.py` с параметрами `protocol.json`. Автоматического подключения к
сайту и финального обучения одного адаптера на всех 40 видео этот запуск не делает.

Все завершённые разбиения и признаки сохраняются. Повтор той же команды
пропускает готовые разбиения; незавершённое начинается заново с исходных весов.
Изменение параметров, кода или данных требует нового `--output`.
`--max-folds 1` позволяет выполнить одно разбиение, затем без этого флага продолжить
остальные. `--prepare-only` проверяет данные и фиксирует протокол без загрузки GPU.
Во время обучения не обновляйте код и не запускайте второй GPU-процесс.

Автоматические вердикты остаются отключены. Скрипт не обучает роли людей,
конкретные категории или локализацию события: соответствующих правильных ответов
нет в таблице. Большая модель и LoRA не гарантируют снижение ошибок.

Локальная проверка: синтетическая уменьшенная InternVideo из закреплённого
исходного кода, Transformers 4.37.2, PyTorch 2.8; проверены реальные токены ответов,
замороженные веса, градиенты, BF16 CUDA и цикл одного разбиения с отчётом.
Полное обучение 8B на сервере PyTorch 2.6/L40S ещё не выполнялось разработчиком.

## Принципы проверки обучения

1. Проверить исходную модель на размеченном открытом наборе, отдельно посчитать ложные тревоги, пропуски и неопределённые ответы.
2. Сгруппировать точные дубликаты по SHA-256. Для каждого проверочного разбиения использовать разные видео для обучения, выбора параметров и итоговой оценки.
3. Дообучить LoRA-адаптер на бинарных метках. Набор из 40 уникальных видео мал; типы нарушений и роли людей в таблице отсутствуют. Не генерировать для них вымышленные правильные ответы.
4. Сравнить дообученную модель с исходной на отложенных видео. Сохранить адаптер и отчёт. Только затем решать, подключать ли модель к приложению.

Обучение меняет веса; запуск analyze.py веса не меняет. Скрипт InternVideo называется train_lora.py. Старый train_full_video.py относится к Qwen и не должен применяться к InternVideo без адаптации.

## Происхождение

Официальный репозиторий: https://huggingface.co/OpenGVLab/InternVideo2_5_Chat_8B
Ревизия: 87680fe232af8681b55322f68541679b91f99df1.
Скачиваются только перечисленные в model-manifest.json файлы. Веса и просмотренный исходный код проверяются SHA-256. Модель использует собственный код из закреплённой ревизии; проверены импорты и пути загрузки/генерации, полный аудит безопасности не проводился.

При анализе включён автономный режим. Видео и ответы не отправляются стороннему AI API. Секреты, видео и веса не включены в архив установки.

## Проверка всех открытых видео

По присланному пользователем результату на L40S анализ Х-48.mov выполнился за 22.71 секунды: 256 кадров, максимальный интервал 0.30042 секунды. Ответ violation ошибочен относительно метки без нарушения. Это подтверждает запуск по пользовательскому скриншоту, но не качество модели. Прямой доступ к серверу и самостоятельная серверная проверка пока отсутствуют.

Загрузите в текущую папку два архива: ForteVision-InternVideo-evaluation.zip и ForteVision-open-dataset.zip. Затем выполните:

```bash
python3 -m zipfile -e ForteVision-InternVideo-evaluation.zip .
python3 -m zipfile -e ForteVision-open-dataset.zip .
.venv/bin/python evaluate_dataset.py --dataset open-dataset --output results/baseline
```

Архив данных содержит 40 уникальных видео, исходную XLSX и manifest.json. Имена точных дубликатов сохранены как aliases. Исходные файлы на ноутбуке не изменены. Этот архив содержит пользовательские видео и не предназначен для публичной публикации.

Скрипт сначала проверяет SHA-256 всех видео, затем загружает модель один раз. Метки используются только после получения предсказания для подсчёта ошибок. Результаты сохраняются после каждого ролика в results/baseline/records.json и metrics.json. При повторном запуске с теми же параметрами завершённые записи пропускаются. Неопределённые ответы и ошибки не считаются правильными отрицательными ответами. Обучение весов не запускается.

После завершения передайте только metrics.json: кадры и описания сцен для обсуждения итоговых чисел не нужны.
# Повтор после ошибки проверки

Обновлённый `evaluate_dataset.py` сохраняет исходный технический traceback в
`results/baseline/error-<sha256>.log` и выводит исходную RuntimeError.
Для повторной попытки сбойных видео с сохранением успешных результатов:

```bash
.venv/bin/python evaluate_dataset.py --dataset open-dataset --output results/baseline --retry-failed
```

Настройки модели и выборки кадров должны совпадать с первоначальным запуском.
Этот режим исправляет диагностику и возобновление, но не устраняет неизвестную
причину GPU-сбоя и не запускает обучение.
