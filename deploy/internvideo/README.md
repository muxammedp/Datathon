# InternVideo: первый запуск на сервере

Этот пакет устанавливает InternVideo2.5-8B и запускает экспериментальный анализ одного видео. Дообучение, трекинг ролей, память между фрагментами и подключение к сайту в этом пакете пока не реализованы. Не считать установку модели обучением или подтверждением качества.

## Запуск в Jupyter

Загрузите ForteVision-InternVideo-server.zip стрелкой Upload в файловой панели Jupyter. В Terminal выполните из папки с архивом:

```bash
python3 -m zipfile -e ForteVision-InternVideo-server.zip .
cd forte-internvideo
bash setup.sh
```

Установка создаёт отдельное окружение .venv, проверяет CUDA и скачивает около 16.8 ГБ весов. Требуются Linux, Python 3.10–3.12, GPU с минимум 40 ГБ памяти и 45 ГБ свободного диска. Компиляция FlashAttention не требуется. Время установки зависит от скорости сети. Аренда сервера продолжает оплачиваться во время установки и простоя; скрипт не управляет оплатой или остановкой инстанса.

После установки загрузите разрешённое видео в эту папку и выполните:

```bash
.venv/bin/python analyze.py "example.mov" --output results/first-video.json
```

Это анализ исходной моделью без дообучения. Ответ экспериментальный, он не передаётся в рабочий API и не является подтверждением нарушения. Параметры по умолчанию: около 4 кадров/сек, максимум 256 выбранных кадров, 448×448, вся выборка в одном контексте. Это НЕ каждый исходный кадр. Кадры кодируются партиями по 16 с сохранением четырёхкадровых групп компрессии. Этот вариант ещё не проверен на L40S; сначала нужно подтвердить запуск и расход памяти.

## Как будет устроено обучение

1. Проверить исходную модель на размеченном открытом наборе, отдельно посчитать ложные тревоги, пропуски и неопределённые ответы.
2. Сгруппировать точные дубликаты по SHA-256. Для каждого проверочного разбиения использовать разные видео для обучения, выбора параметров и итоговой оценки.
3. Дообучить LoRA-адаптер на бинарных метках. Набор из 40 уникальных видео мал; типы нарушений и роли людей в таблице отсутствуют. Не генерировать для них вымышленные правильные ответы.
4. Сравнить дообученную модель с исходной на отложенных видео. Сохранить адаптер и отчёт. Только затем решать, подключать ли модель к приложению.

Обучение меняет веса; запуск analyze.py веса не меняет. Скрипт обучения InternVideo будет подготовлен после проверки загрузки и исходного качества. Старый train_full_video.py относится к Qwen и не должен применяться к InternVideo без адаптации.

## Происхождение

Официальный репозиторий: https://huggingface.co/OpenGVLab/InternVideo2_5_Chat_8B
Ревизия: 87680fe232af8681b55322f68541679b91f99df1.
Скачиваются только перечисленные в model-manifest.json файлы. Веса и просмотренный исходный код проверяются SHA-256. Модель использует собственный код из закреплённой ревизии; проверены импорты и пути загрузки/генерации, полный аудит безопасности не проводился.

При анализе включён автономный режим. Видео и ответы не отправляются стороннему AI API. Секреты, видео и веса не включены в архив установки.

## Проверка всех открытых видео

По присланному пользователем результату на L40S анализ Х-48.mov выполнился за 22.71 секунды: 256 кадров, максимальный интервал 0.30042 секунды. Ответ violation ошибочен относительно метки без нарушения. Это подтверждает запуск по пользовательскому скриншоту, но не качество модели. Прямой доступ к серверу и самостоятельная серверная проверка пока отсутствуют.

Загрузите в текущую папку два архива: ForteVision-InternVideo-evaluation.zip и ForteVision-open-dataset.zip. Затем выполните:

```bash
python3 -m zipfile -e ForteVision-InternVideo-evaluation.zip .
python3 -m zipfile -e ForteVision-open-dataset.zip .
.venv/bin/python evaluate_dataset.py --dataset open-dataset --output results/baseline
```

Архив данных содержит 40 уникальных видео, исходную XLSX и manifest.json. Имена точных дубликатов сохранены как aliases. Исходные файлы на ноутбуке не изменены. Этот архив содержит пользовательские видео и не предназначен для публичной публикации.

Скрипт сначала проверяет SHA-256 всех видео, затем загружает модель один раз. Метки используются только после получения предсказания для подсчёта ошибок. Результаты сохраняются после каждого ролика в results/baseline/records.json и metrics.json. При повторном запуске с теми же параметрами завершённые записи пропускаются. Неопределённые ответы и ошибки не считаются правильными отрицательными ответами. Обучение весов не запускается.

После завершения передайте только metrics.json: кадры и описания сцен для обсуждения итоговых чисел не нужны.
# Повтор после ошибки проверки

Обновлённый `evaluate_dataset.py` сохраняет исходный технический traceback в
`results/baseline/error-<sha256>.log` и выводит исходную RuntimeError.
Для повторной попытки сбойных видео с сохранением успешных результатов:

```bash
.venv/bin/python evaluate_dataset.py --dataset open-dataset --output results/baseline --retry-failed
```

Настройки модели и выборки кадров должны совпадать с первоначальным запуском.
Этот режим исправляет диагностику и возобновление, но не устраняет неизвестную
причину GPU-сбоя и не запускает обучение.
