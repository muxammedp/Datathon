# ForteVision

Локальный прототип для кейса ForteBank с интерфейсом в палитре Forte. Это самостоятельная работа для Datathon, а не официальный банковский продукт.

Для демонстрации серверной модели: [веса, измеренные результаты и вычислительные
ресурсы](MODEL_CARD.md). Новое обучение с повторным использованием кэша:
[events-v3](deploy/internvideo/EVENTS_V3.md). Сайт не является частью этого обновления.

Для отдельного эксперимента InternVideo на Brev: [плотная обработка фрагментов,
визуальная история и обучение по таймкодам](deploy/internvideo/EVENTS.md).
Этот эксперимент ещё не подключён к локальному интерфейсу.

**Qwen3-VL-4B прошла дообучение и отложенную проверку: 55% accuracy, 8 ложных тревог и 10 пропусков на 40 уникальных видео. Качество недостаточно, автоматические вердикты отключены.** Автоматический вердикт включается только при прохождении заданной проверки качества; иначе API возвращает `inconclusive`. Подробности и фактические результаты — в [VALIDATION.md](VALIDATION.md). Старый детектор с ложными категориями выведен из рабочего API.

## Запуск

1. Запустите `Start.cmd`.
2. Откройте http://127.0.0.1:8000.
3. Нажмите «Доступ» и вставьте ключ из `data/api-key.txt` или окна запуска.
4. Выберите MOV / MP4 и запустите анализ.

Окно сервера нужно оставить открытым. Остановка — Ctrl+C. Ключ сохраняется между запусками; в браузере он хранится только в памяти вкладки. Публичного адреса пока нет.

## Что видит модель

Qwen3-VL-4B получает выбранные кадры от начала до конца ролика **в одном видеоконтексте** с фактическими таймкодами. Частота — около двух кадров в секунду, с ограничением 96 кадров на запись. Это не обработка каждого исходного кадра. Короткое действие между выбранными кадрами может быть пропущено.

Внутри запроса модель учитывает всю переданную последовательность. Отдельного проверенного трекера людей и устойчивой идентификации ролей здесь нет. Модель не имеет памяти о других загруженных записях.

Обучение использует до 64 кадров за весь временной диапазон и LoRA в последних 12 слоях, rank=8, q/v-проекции. Визуальный кодировщик и остальные исходные веса заморожены. Его признаки вычисляются локально и кэшируются только для ускорения обучения. Сервер обрабатывает загруженные пиксели, а не ищет ответы по имени или хешу файла.

Разметка содержит только бинарный класс и время. Типы нарушений и роли людей не размечены. Поэтому сервис не утверждает автоматически «кассир ушёл», «не было пересчёта» и другие конкретные обвинения. Каталог нормативных правил используется для ручной проверки.

## Проверка качества

Точные дубликаты объединяются по SHA-256: 42 файла, 40 уникальных видео. В каждом из пяти разбиений проверочные видео полностью исключены из обучения и выбора порога. Часть оставшихся видео используется для выбора эпохи и порога. Кэширование замороженных признаков не использует метки.

Предварительный программный порог включения бинарного вердикта: accuracy >= 0.75, precision >= 0.80, recall >= 0.60, false positive rate <= 0.20, все пять разбиений и минимум 40 уникальных видео. Это инженерный критерий допуска экспериментальной функции, а не гарантия качества на новом ракурсе или закрытом тесте.

Если критерий не выполнен, результат — «Недостаточно оснований для вывода», а список нарушений пуст. Такое воздержание **не считается правильным отрицательным ответом** и не используется для заявления о снижении ложных тревог. Если критерий выполнен, бинарная оценка остаётся экспериментальной; тип события требует проверки. Предлагаемый таймкод базовой модели не является независимым подтверждением.

## API

POST `/api/v1/analyze`: multipart-поле `file`, заголовок `X-API-Key`. Ответ HTTP 202 содержит `job_id`.

GET `/api/v1/jobs/{job_id}` с тем же ключом: статус `processing`, `done` или `failed`.

При `done`:

- `verdict`: `violation`, `no_violation` или **`inconclusive`**;
- `violations`: только поддерживаемые итоговым режимом события; при неопределённости — пустой список;
- `review_required`, `category_status`, `video`, `analysis`;
- `analysis.whole_video_context`, `sampled_frames`, `max_sample_gap_sec` описывают фактическое покрытие;
- у возможного события `rule_id` и `rule` равны null: нормативная категория не обучена.

Третье состояние — сознательное изменение контракта. **Пока модель не прошла проверку, API не является готовым бинарным решением для жюри.** Не преобразовывайте `inconclusive` в «нарушений нет». Ошибки декодирования или модели возвращаются как `failed`.

Сохранённые результаты старой Qwen с неподтверждёнными категориями отзываются при чтении через API и требуют повторной проверки.

GET `/api/health` показывает готовность и `automatic_verdict_enabled`. GET `/api/rules` — справочник. DELETE `/api/v1/jobs/{job_id}` удаляет завершённый результат. Схема: `/openapi.json`.

Ограничения: 150 МБ, 180 секунд, до 4K, одна задача GPU одновременно. HTTP 401 — ключ; 413 — размер; 415 — формат; 422 — нечитаемый файл; 429 — занято; 503 — модель не готова. Исходник удаляется после обработки, результат хранится локально 24 часа.

## Установка и повторное обучение

Python 3.12, совместимый CUDA-драйвер и NVIDIA GPU. Разработка выполняется на RTX 5050 Laptop 8 ГБ. На другом оборудовании время и память нужно измерить заново.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1
```

Установка скачивает зависимости и 4-битные базовые веса. До запуска нужен также обученный адаптер в `models/forte-video-lora-4b-v1` с `adapter_model.safetensors`, `adapter_config.json` и `metadata.json`.

Повторить обучение на разрешённом открытом наборе:

```powershell
.venv\Scripts\python -m pip install -r requirements-research.txt
.venv\Scripts\python scripts/train_full_video.py --dataset "C:\Users\muxammedp\Downloads\open\open" --base-size 4B
```

Не используйте скрытые тестовые видео жюри для обучения. Новые данные, правила подготовки входа или параметры требуют нового каталога эксперимента: существующие кэши и завершённые разбиения используются для продолжения прежнего запуска, а не автоматически считаются совместимыми с любыми изменениями.

Источники весов: [Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), [4-битная версия Unsloth](https://huggingface.co/unsloth/Qwen3-VL-4B-Instruct-bnb-4bit). Ревизия и SHA-256 закреплены в скриптах загрузки. Сторонний код модели не исполняется. Базовая модель занимает около 3,5 ГБ.

Интернет используется при установке. Инференс и обучение выполняются локально; видео, кадры и описания не отправляются во внешние AI API. Выставлены `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`, `HF_HUB_DISABLE_TELEMETRY`, загрузка модели использует `local_files_only=True`.

## Проверки и материалы

```powershell
.venv\Scripts\python -m pytest -q
.venv\Scripts\python scripts/check_frontend.py
node --check app/static/app.js
.venv\Scripts\python scripts/evaluate.py --dataset "C:\Users\muxammedp\Downloads\open\open" --output data/evaluation-current
```

`evaluate.py` проверяет текущий режим сервиса. Качество обученной модели измеряется по отложенным прогнозам в `data/full-video-lora-4b`, а не повторным запуском на её обучающих видео. Флаг `--legacy` воспроизводит снятую с эксплуатации Qwen 2B; её результаты нельзя выдавать за текущий сервис.

`ForteVision-source.zip` содержит исходники, документацию и тесты. Видео, ключ, кэши и базовые веса в архив исходников не включаются. Предыдущие результаты сохранены в [VALIDATION-INITIAL.md](VALIDATION-INITIAL.md).

Docker и публичное размещение требуют отдельной проверки. Серверные эксперименты InternVideo выполнялись на Brev с L40S; сведения в старых отчётах об отсутствии расходов относятся к локальному этапу. Нормативный справочник основан на [Постановлении НБРК № 231](https://adilet.zan.kz/rus/docs/V1900019680); источники и ограничения приведены в каталоге правил.


`ForteVision-adapter-experimental.zip` содержит только обученный адаптер, его конфигурацию и метаданные. Базовые веса, видео, признаки и ключ в него не включены. Проверка качества этого адаптера не пройдена; не выдавайте его за готовый детектор.
